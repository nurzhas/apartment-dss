# Подбор квартиры — СППР (Assignment 4)

Веб-приложение поддержки принятия решений: пользователь задаёт предпочтения, система берёт реальные
объявления **Krisha.kz** по Астане (покупка или аренда) и ранжирует их методами **WSM** и **TOPSIS**
(дополнительно — WPM, AHP, доминирование, анализ чувствительности).

## Запуск

```powershell
.\run.ps1            # создаст .venv при первом запуске и откроет http://127.0.0.1:8100
```

или вручную:

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --port 8100
```

В приложении есть **демо-наборы** (`data/samples/`, сохранённый снимок поиска), поэтому его можно
показать без сети. Новый поиск — слева «Новый поиск на Krisha.kz».

Тесты и консольная демонстрация на примере из лекции 7.1 (поставщики A–D):

```powershell
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m dss.demo          # все шаги 4.2 в консоли; --html сохранит графики
```

## Модель решения

* **Альтернативы** — объявления Krisha.kz, прошедшие жёсткие ограничения (бюджет, комнаты, площадь,
  этаж, год, состояние, расстояние). Предложения застройщиков «от N ₸» и посуточная аренда не берутся.
* **Критерии** (включаются галочкой): цена (cost), цена за м² (cost), площадь, площадь кухни,
  расстояние до выбранной точки (cost, по прямой), год постройки, состояние (балл 1–5), тип дома (1–5),
  этаж (1–3), высота потолков, мебель (1–3), техника и удобства (аренда), число комнат.
* **Веса** — важность 0–10 по каждому критерию, делённая на сумму важностей (Σ = 1), или AHP
  с проверкой согласованности CR ≤ 0.10.
* **Пропуски** в объявлениях: подставить худшее значение (по умолчанию), медиану или исключить объявление —
  что именно подставлено, видно в «Расчёте».

## ИИ-помощник (СППР + генеративный ИИ, лекция 6)

Кнопка «Спросить ИИ» справа внизу и значки «?» у разделов, критериев, графиков, квартир и шагов
«Расчёта» / «Формализации». Модель Claude (`claude-opus-5-5`, официальный SDK `anthropic`) **ничего не
считает сама**: каждое число берётся из инструментов, которые вызывают тот же движок, что и интерфейс
([app/agent.py](app/agent.py)):

| Инструмент | Что делает |
|---|---|
| `get_ranking` | текущий рейтинг по WSM / TOPSIS / WPM |
| `explain_listing` | одна квартира по шагам: значения, r, вклад w·r, d+, d−, C |
| `compare_listings` | 2–5 квартир по каждому критерию |
| `what_if` | пересчёт с другими весами, ограничениями, точкой — экран не меняется |
| `sensitivity` | пороги смены лидера по весу одного критерия |
| `apply_settings` | по просьбе пользователя меняет ползунки и ограничения на экране |
| `lecture_example` | пример поставщиков A–D из лекции 7.1 |
| `get_formalization` | формализация 4.1 |

Ответ приходит потоком (SSE): видны шаги («Разбираю квартиру A12…»), ход рассуждений и текст.
Ключ — `ANTHROPIC_API_KEY` в файле `.env` в корне проекта (файл в `.gitignore`); модель и усилие можно
сменить переменными `ANTHROPIC_MODEL` и `ANTHROPIC_EFFORT` (по умолчанию `medium`). Включён
server-side fallback (`fallbacks: "default"`): если модель откажет по фильтру безопасности, API сам
повторит запрос на рекомендованной резервной модели. Ограничение — 30 вопросов за 10 минут с одного
адреса (сайт может быть открыт через туннель).

## Данные Krisha.kz

Используются только публичные страницы поиска (`/prodazha|arenda/kvartiry/astana/`) и объявлений
(`/a/show/{id}`), ничего из запрещённого в robots.txt (`/ajax/`, `/a/show-map/`, комментарии и т. п.).
Не сохраняются имена, телефоны и свободный текст продавцов.

* Параметры (комнаты, площадь, этаж, цена, тип дома, год, состояние, потолки, мебель, ЖК) берутся
  из **карточек поиска** — 20 объявлений за один запрос.
* **Координаты** — по адресу из карточки через OpenStreetMap Nominatim (1 запрос/с, кэш навсегда):
  дом → улица → ЖК → центр района; точность видна у каждой квартиры.
* Страницы объявлений (точные координаты и больше параметров) открываются только по галочке, с паузой
  3 с. На них у Krisha стоит антибот-защита (SafeLine, HTTP 468): при первом таком ответе клиент
  прекращает открывать объявления на 30 минут — проверка не обходится.
* Кэш — `data/cache.sqlite` (поиск — 30 мин, объявления — 7 дней).
